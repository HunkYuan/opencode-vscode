OpenCode Sidebar 0.1.1 fixes saved GBK source files being absent from the model's context after **Add Current File**.

Previously, the file URI and bytes reached the OpenCode service, but non-UTF-8 source files were classified as `application/octet-stream` and omitted from the model input. The extension now sends the text already decoded by VS Code as a UTF-8 snapshot through the official Composer attachment and Blob pipeline.

- Include the complete source path, saved or unsaved state, and exact selection range in the model-readable attachment.
- Preserve the original file encoding and bytes on disk.
- Keep snapshots in official draft storage so they can be sent after a window reload.
- Re-adding the same file or selection refreshes its snapshot. Capture happens when the attachment is added; re-add it after further edits.

**Upgrade:** Download `opencode-sidebar-0.1.1.vsix`, select **Extensions → Install from VSIX…**, then run **Developer: Reload Window**. Remove attachments retained from 0.1.0 and add the file or selection again.

Requirements: VS Code 1.94 or later and a locally installed OpenCode CLI. The bundled official UI remains pinned to OpenCode 2.1.2.

Validation:
- [Windows and Linux CI](https://github.com/HunkYuan/opencode-vscode/actions/runs/39773765818): lint, typecheck, adapter tests and VSIX build.
- Six actual UI send cases against an isolated service and local model endpoint: saved GBK, saved UTF-8, unsaved file, saved selection, unsaved selection and empty file; requests, service attachments and model input checked.
- Draft reload followed by Send; real VS Code 1.94 GBK decoding, Add Current File and Send; original GBK source bytes unchanged.
- VSIX installation in an isolated VS Code profile.
